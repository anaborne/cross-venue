## What was wrong, and what changed

### 1. The edge-case column repeated the time column

`compare_pairs.py` read `edge_ok = (kcancel==pcancel) and time_ok`. The window
test is false on all 74 pairs, so the edge-case column was false on all 74 and
carried nothing of its own. Three dimensions were published and two were
measured. The line now reads `edge_ok = (kcancel==pcancel)`, `identical` still
ANDs the three columns separately, and the published figure moved from 0 / 74 to
74 / 74 in `README.md` and in §2b of `notes/gateA.md`. The headline of 0 of 74 is
unchanged.

### 2. Every provenance date was a day early, and the ordering claim was false

`git log` gives author dates of 2026-08-29 for all three original commits. The
repository dated the plan commit, the push, the publication and the history
rewrite to 2026-08-28, and `PLAN.md` claimed that commit messages and author
dates preserved the pre-gate ordering. The history is a single squashed initial
commit that already contains `PLAN.md`, `notes/gateA.md` and both artifacts, so
no author date separates before from after. Every date that refers to a commit,
a push or a re-run now reads 2026-08-29, and the redaction note in `PLAN.md`
states that git history does not preserve the ordering and that nothing in this
repository establishes that `PLAN.md` predates the Gate A run.

### 3. A hard cap truncated the Polymarket US walk

`walk()` in `pull_pmus.py` carried `cap=400000` in its loop condition and was
only ever called with the default, so a full-collection walk stopped at offset
399,500 holding 400,000 rows of a collection the repository's own probe sizes
between 542,577 and 542,968, and the reconciliation block reported that as a
complete run. The loop now runs to an empty page, the default cap is 1,000,000,
and reaching the cap on a non-empty page raises. `notes/gateA.md` §5 records it
as the third instance of the same shape.

### 4. Thirty-seven Kalshi join keys disappeared without a count

The reconciliation block accounted for 115 events, 111 join keys and 4 regex
drops, then reported 74 matched pairs. The 37 keys with no Polymarket US
counterpart were never counted or named, and `dropped in evaluation: 0` was
structurally always zero. The script now computes `k_only` and prints the 37
keys, and §2a of `notes/gateA.md` states why 111 reaches 74.

### 5. The 2,448 figure counted parsed markets, not markets of that type

`pg` only ever received markets whose slug matched the regex, so the printed
count was of markets that were both of the right `marketType` and parseable. The
script now counts the type before the slug filter, prints the parsed count and
the unparsed count separately, and `README.md` and §2a of `notes/gateA.md` say
"with a parseable slug".

### 6. The 40-pair minimum was presented as pre-registered

`README.md` and `notes/gateA.md` described a 40-pair sample minimum as part of
the pre-registered set. `PLAN.md` §6 lists five kill criteria and no sample-size
floor. Both files now say the minimum was set in his own notes only, that it is
not written into `PLAN.md` §6, and that it cannot be checked against the
pre-registration file.

### 7. Two [V] counts had no committed script, output or input

§2d's `expiration_time == endDate` and `expected_expiration_time == endDate`
counts, and §2c's five-row phrase census, were marked [V] under a convention that
means a primary source is named inline. `compare_pairs.py` computes none of them
and the committed JSON holds no such field. All three now carry the note that
they were computed inline, that the script is not committed, and that they are
not reproducible from this repository.

### 8. The 27 / 74 source match was a substring hit inside a URL

The test compared the Polymarket US source name against the whole Kalshi
`settlement_sources` entry, name and URL together. On the 27 NFL pairs the Kalshi
name is `the Governing League` and the URL is `https://www.nfl.com/`, so the
token `nfl` matched the hostname and nothing else. The test now splits the name
half off and reads that alone, which scores 0 of 74. `README.md`, §2b and §2e of
`notes/gateA.md` carry the corrected figure and the NFL row of the source table
reads "no, the two names differ".

### 9. `window_hours` searched the whole rules blob

The function ran `re.search` over the entire text and returned on the first
pattern that hit, with days ranked ahead of hours. It now reads only sentences
that mention a postponement, reschedule, delay or suspension, plus a sentence
that names a time window and follows one that does. A pair where either window
cannot be read is now counted and printed in the reconciliation block.

### 10. The Kalshi window was read from half the rules text

`window_hours` was given `rules_secondary` alone on the Kalshi side while the
cancellation test read `rules_primary` and `rules_secondary` together, so a
series stating its postponement clause in the primary text scored a false
negative in the direction of the study's conclusion. Both tests now read the same
concatenated text.

### 11. An unmapped Kalshi series raised `KeyError`

`LG[s]` was an unguarded lookup inside the parse loop, so a pull containing a
fifth sports series would have crashed instead of recording a drop. The lookup is
now `LG.get(s)` and an unmapped series is counted and named in the reconciliation
block. §2e(ii) of `notes/gateA.md` also stated that no NHL pairs entered the
sample because the series had 0 open events; that reason was not established by
this run, and the text now says `KXNHLGAME` is not one of the four series walked
and that its open-event count was not checked.

### 12. The documented reproduce command fails from a fresh clone

The three input files `compare_pairs.py` reads are gitignored, so the command
exits with `FileNotFoundError`. The paragraph described the output as though a
reader could see it. `README.md` now states the failure before describing the
output, and names the two committed artifacts as the evidence for the 74 and the
0.

### 13. `METHOD.md` recovered more markets than it recorded as failed

The sentence read 113 markets failed and a second pass fetched all 115
outstanding. It now reads 113 in both places.

### R2-1. The 2,448 sentence was fixed in one file and left stale in another

`README.md` was corrected and §2a of `notes/gateA.md` was not. §2a now says
"and a parseable slug", and adds that the count of markets of that type before
the slug filter was not recorded by the run and is not recoverable here.

### R2-2. The correction misquoted the line it was correcting

The 2026-09-03 correction quoted the source test without its
`.replace('the ','')`. The line is now quoted in full, matching
`git show d75ea00:src/compare_pairs.py` line 59.

### R2-3. The correction implied the unit ordering was fixed

Only the scope of the search was fixed. Inside one sentence the patterns are
still tried days, then weeks, then hours, so a postponement sentence naming both
a day figure and an hour figure returns the day figure. The correction now says
so, and records that this was not observed on this sample, where every Kalshi
text names one figure.

### R2-4. The narrowed search could return nothing where the old one returned a figure

A rules text that states its operative window in a sentence carrying none of the
four keywords read as unparseable under the keyword-only filter. `window_hours`
now also reads a sentence that names a time window and follows one that does, and
the correction's hedge now names this direction as well: a window figure moving,
or becoming unreadable because the operative sentence carries no postponement
keyword, is [U] on the raw pull.

### R2-5. The plan's own authoring date contradicted the run dates

`PLAN.md` claimed its text was written on 2026-08-28, before Gate A ran. Gate A
ran across 2026-08-27/28. The Provenance section now states that the writing date
sits inside the run window, that the two sub-checks dated 2026-08-27 came first,
that nothing committed here records a time of day, and that the earlier claim was
wrong.

### R2-6. The reproduce paragraph used the present tense for a past run

`README.md` described the current script's output while giving the
pre-correction figures. The sentence now reads "The 2026-08-29 run printed the
reconciliation".

### R2-7. The two stale artifacts carried no in-file pointer

A reader arriving at `notes/compare_pairs.log` or
`data/raw/gateA/pair_comparison.json` by a code-search hit, a raw file link or a
clone saw `src_ok true: 27 / 74` and `edge_ok true: 0 / 74` with no marker. The
log now carries a dated header block above its original 31 lines,
`data/raw/gateA/README.md` states the same about the JSON's two columns and is
un-ignored in `.gitignore`, and §2a of `notes/gateA.md` carries a line under its
reconciliation table pointing at the 37 unmatched keys and at the log's age.

## What this repository cannot establish

The three files `compare_pairs.py` reads are not committed, so the 74 pairs, the
30,720 open markets, the 2,448 typed-and-parsed markets, the 1,462 game keys and
the 111 to 74 join cannot be recomputed here, and neither can the corrected
scorers be run against the data they were written for. The corrected source and
edge-case figures were derived from the committed `pair_comparison.json` and from
the rules text quoted verbatim in §2c and §2f, which is a narrower check than a
re-run. The two committed artifacts predate the 2026-09-03 scorer corrections and
cannot be regenerated for the same reason, so they carry the superseded 27 / 74
and 0 / 74 under a dated notice instead. The §2c phrase census and the §2d
timestamp counts have no committed script. The history is a single squashed
initial commit dated 2026-08-29 that already contains `PLAN.md`, so the
pre-registration ordering rests on the plan text's self-declared date and on the
threshold having been written down before the pull, and neither is checkable
here. The 40-pair sample minimum is not in `PLAN.md` §6.
